Decision trees and ensembles

A sequence of yes/no questions is a model – and one that anyone can read. But a single tree is unstable: a small change in the data rewrites the whole tree. The chapter first splits the test error into bias, variance and noise (we can influence two of them), then shows how a tree is built (CART) and how to combine many trees into a stronger model: bagging and random forest reduce variance, boosting reduces bias.

Bias, variance and noise

Definition: expected value 𝔼

The expected value \(\mathbb E\) of a random variable is its average over all possible values, weighted by their probability. For a continuous variable it is an integral, e.g. for the label \(y\) at the point \(\mathbf x\): \[ \mathbb E_{y\mid\mathbf x}[Y] = \int_y y\,P(y\mid\mathbf x)\,dy \] The subscript says what we average over: \(\mathbb E_T\) over all possible training sets, \(\mathbb E_{\mathbf x, y}\) over all test points and their labels, \(\mathbb E_{\mathbf x, y, T}\) over both at once.

\(\mathbb E\) = “the average if we could repeat the experiment infinitely many times”. For example, read \(\mathbb E_{\mathbf x, y}\big[(h_T(\mathbf x) - y)^2\big]\) like this: take the model \(h_T\), at each test point compute the difference between the prediction \(h_T(\mathbf x)\) and the correct value (ground truth) \(y\), square it (squared error) and average over all possible test points – this is the expected test error (MSE) of this model.

Definition: expected label and expected model

The training set \(T = \{(\mathbf x_1, y_1), \dots, (\mathbf x_n, y_n)\}\) is a random sample from the distribution \(P(X, Y)\), where \(\mathbf x_i\) is the feature vector and \(y_i\) the correct label (supervised learning); the algorithm \(\mathcal A\) turns it into a model \(h_T = \mathcal A(T)\). So the trained model depends on the algorithm and on the training data it happened to get.

  • The expected label is the best possible prediction at the point \(\mathbf x\): \[ \bar y(\mathbf x) = \mathbb E_{y\mid\mathbf x}[Y] \]
  • The expected model is the average of the models the algorithm would produce from all possible training sets: \[ \bar h = \mathbb E_{T\sim P^n}[h_T] \]

\(\bar y\) is “the truth without noise”, \(\bar h\) is what our algorithm “can do on average”. If we had infinitely many training sets, we would average the models learned from them and get \(\bar h\) – the “ideal” model of the algorithm, as if it learned from all data in the world. In practice we never have it; it serves to split the error into parts.

Decomposition of the expected test error (MSE)
\[ \begin{aligned} &\underbrace{\mathbb E_{\mathbf x, y, T}\big[(h_T(\mathbf x) - y)^2\big]}_{\text{expected test error}} \\ &\quad= \underbrace{\mathbb E_{\mathbf x, T}\big[(h_T(\mathbf x) - \bar h(\mathbf x))^2\big]}_{\text{variance}} \\ &\quad+ \underbrace{\mathbb E_{\mathbf x}\big[(\bar h(\mathbf x) - \bar y(\mathbf x))^2\big]}_{\text{bias}^2} \\ &\quad+ \underbrace{\mathbb E_{\mathbf x, y}\big[(\bar y(\mathbf x) - y)^2\big]}_{\text{noise}} \end{aligned} \]
variancehow much the model changes when we change the training data
bias²how far the average model is from the best possible prediction (systematic error of the algorithm)
noiseirreducible error of the data – no algorithm and no amount of data removes it

In words: the squared error averaged over all test points, their labels and all possible training sets splits into three parts – how much the model “wobbles” depending on the data it got (variance), how much its average is systematically wrong (bias²) and how much the labels themselves vary around their expected value (noise). All three terms are non-negative, so the test error never drops below the noise.

Derivation: “add and subtract” twice – first \(\bar h(\mathbf x)\), then \(\bar y(\mathbf x)\) – and expand \((a + b)^2 = a^2 + 2ab + b^2\). The cross terms drop out:

  • the first because \(\mathbb E_T[h_T(\mathbf x)] = \bar h(\mathbf x)\),
  • the second because \(\mathbb E_{y\mid\mathbf x}[y] = \bar y(\mathbf x)\).
Definition: bias–variance trade-off, underfitting and overfitting

The bias–variance trade-off is the effect that increasing model complexity usually lowers the bias and raises the variance. Underfitting = the model is too simple, it has high bias (a large error already on the training data). Overfitting = the model is too complex, it has high variance (low training but high test error – it has learned the noise).

a simple model “misses the shape” but is stable; a complex model hits the shape but “jumps around” depending on which data it happened to get. The optimum is in the middle. Noise is the floor we cannot go below.

Watch out: noise is irreducible only for the given features

Noise does not depend on the model or its complexity (in the error plot it is a horizontal line) – neither a better algorithm nor more data reduces it. But it is defined with respect to the features \(\mathbf x\) the model works with. When we add a new informative feature (e.g. another measurement of the patient), \(\bar y(\mathbf x)\) changes and part of the former “noise” becomes explainable. That is not a better model, though, but a different task with more information.

Bias = how far the centre of the cluster of dots (the average model \(\bar h\)) is from the centre of the target – it is a systematic error that does not disappear even if we average infinitely many models. Variance = how scattered the dots are around their centre – how sensitively the model reacts to the data it happened to get. Low bias and low variance (top left) is the goal. High bias with low variance (bottom left) is a typical underfitted model – e.g. a line on curved data: almost the same every time, wrong in the same way every time. Low bias with high variance (top right) is a typical overfitted model – e.g. a deep tree: on average it hits the target, but every training set gives a completely different model. Noise is not in the picture – it would “blur” even the centre of the target itself.

Curves. With model complexity (tree depth, polynomial degree, small \(k\) in k-NN, large \(C\) in SVM…) bias² decreases (the model can express a more complex shape) and variance increases (the model has more freedom to adapt to noise). The total test error is their sum plus noise, so it has a “U” shape: on the left bias dominates (underfitting), on the right variance (overfitting). The minimum (“sweet spot”) is where the improvement in bias is balanced by the worsening of variance – we find it by validation. Noise is a horizontal floor below which no model can push the total error.

What to take from the figure

As the number of samples grows, the training error goes up (more points are harder to “memorize”) and the test error goes down (more data = a better estimate); both approach the same value. The test curve lies above the training curve – on data the model has seen, it makes fewer errors on average. Regime 1 – high variance (left): the training error is below \(\varepsilon\), the test error above it, and there is a large gap between them; the gap is exactly the variance. Extreme case: the training set has only 2 patients – the model simply memorizes them (training error 0), but on new patients its error is huge; this is overfitting. The test curve is still falling, so more data will help, as will a simpler model or bagging. Regime 2 – high bias (right): both curves have already met, but above \(\varepsilon\). We may have millions of patients and more data will not help – the curves converged in the wrong place; you need a more complex model, more features or boosting. At the exam: “first I look at the learning curves to know in which direction to change the model.”

Decision trees

Definition: decision tree and its parts

A decision tree is a model that classifies a sample (or predicts a value) by going from the root to a leaf: each inner node asks one binary question about one feature (e.g. \(x_1 \gt \frac14\)), a branch is the answer and a leaf (terminal node) holds the resulting class or value. The size of a tree is the number of nodes (splits), the depth is the length of the longest path from the root to a leaf. A tree with a single node is a stump.

“twenty questions”: Does it have fur? Does it have four legs? … The questions can be about numeric (\(x_1 \gt \frac14\), number of legs), categorical (skin = fur) and binary (is it cute?) features. A prediction costs as many questions as the depth of the tree – it does not depend on the number of training samples. A tree is interpretable: for each prediction we know which path (which answers) led to the decision.

CART

Definition: CART

CART (Classification And Regression Trees, Breiman et al. 1984) is an algorithm that builds a tree by recursive binary splitting: in each node it chooses one feature \(j\) and a threshold \(s\) that reduce the impurity (error) of the two resulting regions the most; it thus splits the feature space into axis-parallel rectangles. It is defined by three rules: the splitting criterion, the stopping rule and the rule for the leaf value (majority class or mean).

“find the question that splits the data most cleanly, and repeat it in each half”.

Splitting criterion (classification)
\[ E_k = \min_{j\in\{1,\dots,d\},\ s\in\mathbb R}\left[E_{R_k}(j, s) + E_{R_k^C}(j, s)\right] \] \[ \begin{aligned} R_k(j, s) &= \{\mathbf x_i: x_{ij} \gt s\} \\ R_k^C(j,s) &= \{\mathbf x_i: x_{ij} \le s\} \\ E_{R} &= \textstyle\sum_{i:\mathbf x_i\in R}I(y_i \ne \hat y_R) \end{aligned} \]
\(j, s\)feature and threshold – we minimize over both
\(R_k, R_k^C\)the two complementary regions created by splitting the \(k\)-th node
\(\hat y_R\)majority class of the region (the leaf value)
\(I(\cdot)\)indicator – counts misclassified points

In words: each split uses a single feature, so the question is: which feature \(j\) and which threshold \(s\)? For every pair \((j, s)\) we split the points of the node into two parts (\(x_{ij} \gt s\) and \(x_{ij} \le s\)). In each part we label all points with its majority class and count how many of them end up wrong (\(E_R\)). We add the two counts and choose the pair with the smallest sum. It is enough to try thresholds between neighbouring values of the feature, so brute force works; the same search is then repeated in every new region.

Lecture example (19 points, 10 : 9): without a split there are 9 errors. The best first cut is \(x_2 \gt 0.25\) – 5 errors stay in the upper region and 1 in the lower one, so \(E = 5 + 1 = 6\).

In practice Gini or entropy is used instead of the number of errors (see below). In regression the criterion is the sum of squares \(\sum_{i\in R}(y_i - \hat y_R)^2\) and the leaf value is the mean – the model is piecewise constant (“steps”). In words: how much the values \(y\) in the region spread around its mean (the mean squared error times the number of points).

Watch out: E in CART is not the expected value

In the test error decomposition, \(\mathbb E\) is the expected value (an average). In CART, \(E_k\) and \(E_R\) mean the error of a node or region – the number of misclassified points (the sum of squares in regression). Same letter, different meaning.

Greedy tree growing
  1. For each region compute the best split – go through the features \(j\) and thresholds \(s\) (by brute force or using histograms).
  2. Take the best region (with the lowest error) and split it by that feature and threshold into two subregions.
  3. Repeat for each new subregion until a stopping rule applies.

“Greedy”, because every split is locally the best and is never undone; searching for the globally best tree would be combinatorially impossible. In the lecture example (19 points) five splits reduce the number of errors 9 → 6 → 5 → 4 → 3 → 1 and the sum \(\sum_R n_RG_R\) from 9.47 to 1.60; the last leaf (4 : 1) stays impure because growth is stopped by max_depth = 3.

Definition: node impurity measures

For the class proportions \(p_R(y)\) in a region \(R\):

  • error rate \(1 - \max_yp_R(y)\);
  • entropy \(H_R = -\sum_y p_R(y)\log p_R(y)\);
  • Gini impurity \[ G_R = \sum_y p_R(y)(1 - p_R(y)) = 1 - \sum_y p_R(y)^2 \]

All are zero for a pure node (a single class) and maximal when the classes are equally represented. In words:

  • error rate = the share of points that do not belong to the majority class of the node;
  • entropy = how many bits we need on average to find out the class of a randomly chosen point from the node;
  • Gini = the probability that we classify a randomly chosen point wrongly if we assign its class at random according to the class shares in the node.

“how mixed the node is”. Gini and entropy are smooth and strictly concave, so they also reward a split that does not change the number of errors but makes one of the nodes purer – that is why they are preferred in practice.

By hand (lecture, two classes, log₂)

Leaf 4 : 1 (\(p = 0.8\)): 1 error (error rate 0.2); \(H = -0.8\log_20.8 - 0.2\log_20.2 = 0.72\) bits; \(G = 0.8\cdot0.2 + 0.2\cdot0.8 = 0.32\). Root 10 : 9: \(H = 1.00\) bit, \(G = 0.50\). Pure leaf: all three are zero.

What to take from the figure

All three measures are zero at the edges (pure node) and maximal at \(p = 0.5\). The error rate is piecewise linear – many splits get the same score. Entropy and Gini are curved, so they tell apart a “purer” split even with the same number of errors.

When to stop splitting

  • the region contains a single point; split only if the region has more than \(n_{\min}\) points;
  • the region contains points of a single class;
  • the maximum tree depth or the maximum number of splits (size) is reached.

Without rules the tree grows until every leaf is pure – on the wine data (115 training, 63 test points) the training accuracy grows to 1.00, the test accuracy peaks at depth 2 (0.87) and ends at 0.83 (lecture). An alternative to stopping is pruning: let the tree grow fully and then cut off branches that do not improve the validation error.

What to take from the figure

A tree splits the space into axis-parallel rectangles. Depth 1 (a stump) can make only one cut – two of the three classes (underfitting). Depth 3 captures the structure. Depth 10 makes narrow strips around individual points: training accuracy 1.00, test accuracy no longer grows. Training accuracy always grows with depth, test accuracy stops and can drop.

Ensembles and bagging

Definition: ensemble method

An ensemble method combines many base models (here trees) into one stronger and more complex model: bagging by a simple average, boosting (AdaBoost) by a weighted average; plus many variants (LPBoost, RUSBoost, RobustBoost, XGBoost…).

“the wisdom of the crowd”. Bagging attacks the variance, boosting the bias.

Definition: bootstrap sample and bagging

A bootstrap sample is a random selection of \(n'\) samples from the training set with replacement (usually \(n' = n\)), so some samples appear in it several times and others not at all. Bagging (bootstrap aggregation) trains \(M\) models on \(M\) bootstrap samples and averages their predictions: \(h_{\text{bagg}}(\mathbf x) = \frac1M\sum_{m=1}^Mh_{T_m}(\mathbf x)\) (majority vote for classification).

each tree sees slightly different data and so makes slightly different mistakes; when averaging, the random errors of the individual trees cancel each other out. The bias stays (an average of similarly deep trees), the variance drops.

Variance of the average of M trees

Independent trees:

\[ \operatorname{Var}[h_{\text{bagg}}(\mathbf x)] = \frac{\sigma_1^2}{M} \]

Correlated trees (correlation \(\rho\)):

\[ \operatorname{Var}[h_{\text{bagg}}(\mathbf x)] = \rho\,\sigma_1^2 + \frac{1 - \rho}{M}\sigma_1^2 \]
\(\sigma_1^2\)variance of the prediction of one tree (over training sets)
\(M\)number of trees in the average
\(\rho\)correlation between trees – the trees share the same data, so they are not independent

In words: for independent trees the variance of the average drops \(M\) times. For correlated trees it has two parts. The term \(\rho\sigma_1^2\) is the error the trees share (they see the same data, so they make similar mistakes) – averaging does not remove it. The term \(\frac{1-\rho}{M}\sigma_1^2\) is their own random errors – these cancel out in the average. The smaller the correlation, the more bagging helps.

As \(M\) grows the second term vanishes, but the first \(\rho\sigma_1^2\) stays – the variance does not drop below \(\rho\sigma_1^2\). In the lecture: going from one bootstrap tree to \(M = 50\) reduced the prediction variance from 0.00465 to 0.00175 – 2.7×, not 50×. (Plugging in gives \(\rho \approx 0.36\).) That is why random forest additionally “decorrelates” the trees.

What to take from the figure

A single tree “jumps” depending on the data it got (mean prediction variance 0.165); the bagged predictions for the same 20 sets are much closer together (0.095) and smoother. The average over the sets (\(\approx\bar h\)) is similar for both – bagging does not change the bias. Right: the more correlated the trees are, the sooner the drop in variance stops.

Random forest

Definition: random forest

Random forest is bagging of decision trees with one extra source of randomness: at each node split the tree may only choose from a random subset of features. It therefore has two independent sources of randomness – which samples a tree sees (bootstrap) and which features each split may use.

if one feature were very strong, all bagged trees would mainly ask about it and would be similar to each other (high \(\rho\)). The random choice of features forces them to be diverse, the trees are less correlated, and so averaging pays off more. Random forest is thus the answer to the question: how to reduce the correlation of the trees so that bagging is effective?

Definition: out-of-bag (OOB) samples

The out-of-bag samples of a tree are the training samples that did not get into its bootstrap sample (the others are in-bag); they serve as validation data. Each tree has different OOB samples, i.e. its own validation set. The OOB score of a sample is computed only from the trees for which that sample is OOB.

a bootstrap of size \(n\) leaves out each sample with probability \((1 - 1/n)^n \to e^{-1} \approx 37\,\%\) (for \(n = 10\): 0.35; \(n = 100\): 0.366) – hence the rule “2/3 in-bag, 1/3 OOB”. This gives an estimate of the test error without cross-validation – useful with small data. But each sample is evaluated by only ≈ 1/3 of the trees, so the OOB score tends to be slightly pessimistic; do not mix OOB and validation scores when comparing models.

What to take from the figure

With the number of trees the error drops and then levels off – more trees do not overfit, they only cost more computation. max_features = all features is plain bagging (correlated trees); √d (≈ 4) gives the lowest error; 1 feature per split weakens the trees too much (each split is almost random, higher bias).

Adaptive boosting (AdaBoost)

Definition: AdaBoost

AdaBoost is an ensemble method that trains weak classifiers \(h_m\) one after another, each on reweighted data (misclassified samples get a higher weight), and the result is their weighted vote (for classes \(\pm1\)): \[ H(\mathbf x) = \operatorname{sign}\Big(\sum_{m=1}^M\alpha_mh_m(\mathbf x)\Big) \]

each next “weak learner” focuses on what the previous ones got wrong, and a better learner has a stronger voice in the final vote. Many simple ones (typically stumps) make up a strong, complex classifier – boosting reduces bias.

Principle: AdaBoost = a weighted vote of stumps

The weak classifier in AdaBoost is most often a stump – a tree with a single split, i.e. one axis-parallel cut “+1 on one side, −1 on the other”. On its own it is weak, only a bit better than chance. AdaBoost trains \(M\) of them one after another and the result is their weighted sum: each stump votes \(+1\) or \(-1\), its vote is multiplied by its weight \(\alpha_m\) and the sign of the sum decides the class. A few straight cuts thus make a “staircase”, non-linear boundary (Fig. 6.10).

Two kinds of weights – do not mix them up:

  • sample weight \(w_i\) – how much the next stump should care about sample \(i\); it changes after every round;
  • stump weight \(\alpha_m\) – how strong the vote of stump \(m\) is in the final vote; it is computed once and never changes.

How the sample weights change:

  1. At the start all samples are equally important: \(w_i = 1/n\).
  2. The stump is chosen by its weighted error \(\epsilon_m\) = the sum of the weights of misclassified samples. Getting a “heavy” sample wrong costs a lot, a “light” one little – so it pays to get the heavy samples right.
  3. After the round, the weight of every correctly classified sample is multiplied by \(e^{-\alpha_m} \lt 1\) (it drops) and of every misclassified one by \(e^{+\alpha_m} \gt 1\) (it grows). The more accurate the stump (larger \(\alpha_m\)), the stronger the reweighting.
  4. Dividing by \(Z_m\) makes the weights sum to 1 again – the weights are “shares of attention” that only move between samples.

After reweighting, the misclassified samples hold exactly half of the total weight together. On the new weights the stump just trained is therefore as good as a coin toss (\(\epsilon = 0.5\)), and the next round has to find a different cut – one that fixes the mistakes so far.

AdaBoost algorithm (data \(\mathbf x_i\in\mathbb R^d\), \(y_i\in\{-1,+1\}\))
  1. Initialize the sample weights \(w_i^{(1)} = 1/n\).
  2. Find the weak classifier \(h_m\) with the smallest weighted error \(\epsilon_m = \sum_{i: h_m(\mathbf x_i)\ne y_i}w_i^{(m)}\).
  3. Compute its weight \(\alpha_m = \frac12\ln\frac{1 - \epsilon_m}{\epsilon_m}\).
  4. Reweight the samples: \(w_i^{(m+1)} = w_i^{(m)}e^{-\alpha_my_ih_m(\mathbf x_i)}/Z_m\), where \(Z_m = \sum_iw_i^{(m)}e^{-\alpha_my_ih_m(\mathbf x_i)}\) normalizes the weights to sum to 1.
  5. Repeat 2–4 for all \(M\) weak classifiers.

Correctly classified samples (\(y_ih_m = +1\)) lose weight (\(e^{-\alpha}\)), wrong ones gain it (\(e^{+\alpha}\)). At \(\epsilon_m = 0.5\) (chance) \(\alpha_m = 0\) – the classifier has no vote; the smaller the error, the larger \(\alpha_m\).

In words, the formula for \(\alpha_m\): the fraction \(\frac{1 - \epsilon_m}{\epsilon_m}\) is the ratio “weight the stump got right : weight it got wrong”. A stump that gets 70 % of the weight right has the ratio 70 : 30:

\[ \alpha = \tfrac12\ln\tfrac{0.70}{0.30} = \tfrac12\ln 2.33 = 0.42 \]

The logarithm makes sure that a stump at chance level (50 : 50, ratio 1) gets \(\alpha = 0\) and a stump worse than chance gets a negative weight – its vote is flipped.

AdaBoost step by step (lecture: 10 samples, 3 stumps)
  1. All weights 0.10. The first stump misclassifies 3 samples: \(\epsilon_1 = 3\cdot0.10 = 0.30\), \(\alpha_1 = \frac12\ln\frac{0.70}{0.30} = 0.42\). (Own calculation: \(Z_1 = 0.917\); correct samples get weight 0.071, wrong ones 0.167.)
  2. The second stump on the reweighted data gets the three “hard” blue ones right and misclassifies three easy red ones: \(\epsilon_2 = 3\cdot0.07 = 0.21\), \(\alpha_2 = 0.65 \gt \alpha_1\).
  3. The third (horizontal) one misclassifies three of the four lightest samples (each exactly 1/22): \(\epsilon_3 = 0.14\), \(\alpha_3 = 0.92\).
  4. \(H(\mathbf x) = \operatorname{sign}(0.42h_1 + 0.65h_2 + 0.92h_3)\) – three axis-parallel stumps give a non-trivial region that classifies all 10 samples correctly.

What to take from the figure

For the two blue samples on the left, \(h_1\) and \(h_2\) vote blue and \(h_3\) votes red:

\[ 0.42 + 0.65 - 0.92 = 0.15 \gt 0 \;\Rightarrow\; \text{blue} \]

So they are classified correctly even though the strongest stump got them wrong. For the red sample top right we get \(-0.42 - 0.65 + 0.92 = -0.15\), i.e. red. The resulting boundary has a staircase shape that no single stump can draw, and it classifies all 10 samples correctly.

What to take from the figure

One stump = one cut (high bias). Each round adds a cut where mistakes were made so far – the boundary becomes more and more complex and the bias drops (test 0.82 → 0.90). At 300 rounds the training accuracy reaches 1.00 thanks to narrow “spikes” around individual points. Label noise (lecture): three mislabelled samples out of 80 start with 3.75 % of the total weight and after 40 rounds hold 37 %; the training error is 0 thanks to strips narrower than 0.01 around them – AdaBoost is sensitive to wrong labels.

Other tree algorithms and pruning

Definition: information gain (ID3)

The information gain of a feature is the difference between the entropy of the target before the split and the weighted (expected) entropy after splitting by the values of the feature. The ID3 algorithm (Quinlan 1986) splits each node by the feature with the largest information gain; it works only with categorical features. C4.5 / C5.0 is its modification that also handles numeric features.

“how many bits of uncertainty about the target I lose when I ask about this feature”. Procedure: total information → expected information for each feature → gain → split by the largest → repeat recursively.

Pruning: first let the whole tree grow and then cut off branches that do not improve the validation error – an alternative to stopping rules.

How to say it at the exam

“The expected test error splits into variance – how much the model changes with the training data –, bias² – how far the average model is from the best prediction – and irreducible noise. A large gap between training and test error means high variance: more data, a simpler model or bagging help. A high error even on training means bias: a more complex model, features or boosting help. CART builds a tree greedily – in each node it chooses the feature and threshold minimizing Gini or entropy – and stops by depth or leaf size. A tree is readable but unstable. Bagging averages trees from bootstrap samples and reduces variance, limited by the correlation of the trees; random forest decorrelates them by a random choice of features per split and offers an OOB error estimate. AdaBoost combines weak classifiers – typically stumps – trained one after another on reweighted data and weights them by \(\alpha_m = \frac12\ln\frac{1-\epsilon_m}{\epsilon_m}\); it reduces bias but is sensitive to label noise.”

Summary

Test error = variance + bias² + noise; model complexity balances bias and variance, and learning curves show which one dominates. A decision tree asks binary questions about single features and splits the space into axis-parallel rectangles; CART builds it greedily by impurity (Gini, entropy; squares for regression) and stops by depth, leaf size or purity, or prunes. A tree does not need scaling, but it is unstable and a deep one overfits. Bagging averages trees trained on bootstrap samples and reduces variance, but only down to \(\rho\sigma^2\); random forest adds a random subset of features per split, which decorrelates the trees, and the OOB samples (≈ 37 %) give an error estimate without CV. AdaBoost adds weak classifiers (typically stumps) one after another on reweighted data with weights \(\alpha_m\), reduces bias but overfits on wrong labels. ID3 splits by information gain.

Take-home messages

  1. Error = variance + bias² + noise; you cannot remove the noise.
  2. Large train–test gap = variance (more data, simpler model, bagging); high error everywhere = bias (more complex model, boosting).
  3. CART: greedy splitting by Gini/entropy, axis-parallel cuts, no scaling.
  4. ↑max_depth and ↓min_samples_leaf = more complex tree = overfitting.
  5. Bagging reduces variance only down to \(\rho\sigma^2\) – RF decorrelates the trees by feature sampling.
  6. More trees in RF do not overfit; OOB ≈ 1/3 of the data as free validation.
  7. AdaBoost: \(\alpha_m = \frac12\ln\frac{1-\epsilon_m}{\epsilon_m}\), reweights the mistakes; sensitive to label noise.

Exam questions

Write the decomposition of the expected test error into bias, variance and noise. Which terms can we influence and how?

Decomposition of the expected test error:

\[ \begin{aligned} \mathbb E[(h_T(\mathbf x) - y)^2] &= \mathbb E[(h_T - \bar h)^2] && \text{variance} \\ &+ \mathbb E[(\bar h - \bar y)^2] && \text{bias}^2 \\ &+ \mathbb E[(\bar y - y)^2] && \text{noise} \end{aligned} \]

\(\bar h\) is the average model over training sets, \(\bar y\) the expected label. The cross terms drop out because \(\mathbb E_T[h_T] = \bar h\) and \(\mathbb E_{y|\mathbf x}[y] = \bar y\). We can influence the variance (more data, a simpler model, bagging, regularization) and the bias (a more complex model, more features, boosting); not the noise.

What does 𝔼 mean in the test error decomposition and what does its subscript tell us?

\(\mathbb E\) is the expected value – the average over all possible values, weighted by their probability. The subscript says what we average over:

  • \(\mathbb E_T\) over all possible training sets – this gives the average model \(\bar h\);
  • \(\mathbb E_{y\mid\mathbf x}\) over the possible labels at a fixed point \(\mathbf x\) – this gives the expected label \(\bar y(\mathbf x)\);
  • \(\mathbb E_{\mathbf x, y}\) over test points and their labels.

The expected test error \(\mathbb E_{\mathbf x, y, T}[(h_T(\mathbf x) - y)^2]\) is therefore the squared error (prediction minus ground truth, squared) averaged over all possible test data and all possible training sets. Watch out: \(E_k\) in CART is something else – the number of misclassified points in a node.

You see a large gap between training and test error. Which regime is it and what do you do? And when the training error is above ε?

A large gap (training < ε < test) = high variance: more training data, a simpler model (smaller depth, regularization), bagging. Training error above ε and test error close to it = high bias: more data will not help (the curves have already converged to a bad value); a more complex model, more features or boosting are needed.

Define node, leaf, branch, size and depth of a tree. What is a stump? Write the CART splitting criterion.

Node = a binary question about one feature; leaf = a terminal node with the answer; branch = the answer to a question; size = number of nodes (splits); depth = the longest root–leaf path; stump = a tree with a single node. CART minimizes, over the feature \(j\) and the threshold \(s\), the sum of the errors (impurities) of both resulting regions \(E_{R_k}(j,s) + E_{R_k^C}(j,s)\), \(R_k = \{x_{ij} \gt s\}\). It is greedy – it picks the locally best split and does not go back; a globally optimal tree would be combinatorially out of reach.

Compare error rate, entropy and Gini. Compute them for a leaf 4 : 1.

Error rate \(1 - \max p\), entropy \(-\sum p\log_2p\), Gini \(\sum p(1-p)\); all are 0 for a pure node, maximal when classes are equally represented. Leaf 4 : 1: error rate 0.2 (1 error), entropy 0.72 bits, Gini 0.32. Gini and entropy are smooth and concave, so they also reward a split that does not change the number of errors but creates a purer node – that is why they are preferred for growing.

How does a regression tree differ from a classification tree?

The splitting criterion is the sum of squared deviations from the mean of the region instead of impurity; the leaf value is the mean of \(y\) of the points in the leaf instead of the majority class; the resulting function is piecewise constant (“steps”).

What is a bootstrap? Why should the average of M trees reduce the variance M times, and why only 2–3× in practice?

Bootstrap = selecting \(n\) samples with replacement. The variance of the average of \(M\) independent variables is \(\sigma^2/M\). But trees from bootstraps of the same data are correlated (correlation \(\rho\)): \(\operatorname{Var} = \rho\sigma^2 + (1-\rho)\sigma^2/M\) – the first term does not decrease with \(M\). In the lecture \(M = 50\) reduced the variance only 2.7× (corresponds to \(\rho \approx 0.36\)).

What does random forest add to bagging and why does it help? What are OOB samples?

At each split only a random subset of features is considered (typically √d). The trees are more diverse and less correlated, so averaging reduces the variance more. The OOB samples of a tree are those that did not get into its bootstrap – \((1 - 1/n)^n \to e^{-1} \approx 37\,\%\); they serve as validation data and give an error estimate without CV. Each sample is evaluated by only ≈ 1/3 of the trees, so OOB is slightly pessimistic and should not be mixed with validation scores.

Write the AdaBoost prediction rule and the formula for αₘ. What does αₘ do at εₘ = 0.5? How are the weights updated and what is Zₘ for?

The final classifier and the weight of one classifier:

\[ H(\mathbf x) = \operatorname{sign}\Big(\sum_m\alpha_mh_m(\mathbf x)\Big) \] \[ \alpha_m = \frac12\ln\frac{1-\epsilon_m}{\epsilon_m} \]

At \(\epsilon_m = 0.5\) we get \(\alpha_m = 0\) – a random classifier has no vote, with a small error the weight is large. Update of the sample weights:

\[ w_i \leftarrow \frac{w_i\,e^{-\alpha_my_ih_m(\mathbf x_i)}}{Z_m} \]

Misclassified ones grow, correct ones shrink; \(Z_m\) is the normalization constant so that the weights sum to 1. In the lecture example, after the first stump the three misclassified samples have weight 0.17 and the others 0.07, so the second stump gets them right and instead misclassifies three light samples. The result is a weighted vote of stumps that together form a staircase boundary. Sensitivity to noise: a mislabelled sample is “always wrong”, its weight grows round after round and the next classifiers try to get it right at any cost.

Bagging vs. boosting: which error term does each reduce and which can be parallelized?

Bagging (and random forest) reduces variance by averaging independently trained (deep) trees – parallelizable. Boosting reduces bias by adding weak classifiers one after another, each focused on the mistakes of the previous ones – sequential, it cannot be parallelized.
